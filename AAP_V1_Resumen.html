AAP V1 Laboratory

Autonomous Agent Platform — Plataforma de Agentes Autónomos Completamente Funcional

Resumen Ejecutivo

AAP V1 es una plataforma de runtime para agentes definidos por datos, no por código. Los agentes se configuran enteramente a través de una definición JSON (Agent Definition) — sin escribir YAML, Python, ni declarar herramientas en código. Todo es declarativo, versionable, y ejecutable desde una interfaz web.

Tres Bases de Datos Inmutables

Base de Datos Propósito Contenido Clave

domain.db Datos específicos del dominio Entidades, tablas genéricas, datos de negocios

Flujo de Ejecución

  • API (FastAPI) — Recibe definiciones, crea runs, los encola (nunca ejecuta en el hilo de la petición HTTP)
  • Cola de Runs — Runs nuevos se guardan con status="queued" en runtime.db
  • Worker (proceso separado) — Polling cada 2s, reclama runs, los ejecuta con el Executor
  • Executor (core/runtime/executor.py) — Orquesta L0-L3 de autonomía, emite eventos, actualiza estado
  • Policy Engine (chokepoint) — Todos los tool calls pasan por comprobación de política antes de ejecutar
  • Persistencia — Cada evento, tool_call, y cambio de estado se registra inmediatamente (sin pérdida de datos)

Características Principales

  • Definición 100% declarativa — Agentes viven como JSON, no código
  • Sin escribir código — Crear, editar, versionar agentes desde la UI
  • Policy Engine mandatorio — Todas las tools pasan por comprobaciones antes de ejecutar
  • 4 niveles de autonomía — L0 (fijo), L1/L2 (react/plan), L3 (iterativo con replanificación)
  • Event log completo — Cada acción registrada, auditable, reproducible
  • Presupuesto garantizado — Límites en steps, tool_calls, tokens, dinero, wallclock
  • Versionado inmutable — Cada versión es un snapshot congelado
  • Comparación v1/v2 — Ver exactamente qué cambió en definición y métricas
  • Evaluación determinista — Eval sets fijos, sin LLM real, resultados reproducibles
  • Ejecución asincrónica real — HTTP API nunca bloquea, worker ejecuta en paralelo
  • Persistencia robusta — SQLite en volúmenes Docker, survives restart
  • UI sin build — HTML/CSS/JS plano, la API los sirve como estáticos

Decisiones Arquitectónicas Clave

Pydantic como Fuente de Verdad Única

Los schemas Pydantic generan el JSON schema de la UI automáticamente. Añadir un campo al modelo → nuevo control en el formulario, sin tocar JavaScript.

Policy Engine como Chokepoint

No hay bypass a la policy engine. Ni siquiera el executor puede invocar una tool sin pasar por ahí primero. Las políticas se declaran a nivel de agente, no de sistema.

Async Execution = HTTP Nunca Bloquea

POST /runs devuelve 202 Accepted inmediatamente. El worker ejecuta en otro proceso. Esto escala a miles de runs simultáneos sin bloquear el servidor.

Redacción en Persistencia, No en Display

Los secrets se redactan ANTES de guardar en DB, así el audit trail es limpio desde el principio.

Factory Pattern para Versionado

Duplicar un agente, modificarlo, promover una versión, archivar la anterior — todo respetando que las versiones son snapshots congelados.

Exclusiones Deliberadas de V1

Por diseño, V1 se enfoca en "fea pero funcional". Explícitamente fuera del alcance (para V2+):

  • Scraping web real (solo mock)
  • Modelos locales (Qwen, GPU) — solo routers a providers reales
  • WhatsApp/Android/Slack nativo
  • Canvas visual para workflows
  • Juez-LLM (eval set sí, pero comprobaciones puramente programáticas)
  • Multi-tenancy / RBAC
  • Cola de aprobaciones desde UI (DENY funciona, pero no hay pantalla para aprobar)

Cómo Ejecutar

Local (sin Docker)

pip install -e ".[dev]"
uvicorn aap.api.main:app --reload --port 8080
# en otra terminal:
python -m aap.worker.main

Con Docker

docker compose up -d
curl http://localhost:8080/health
# → {"status":"ok","api":true,"worker":true,"db":true}

Abrir la UI

http://localhost:8080 → Dashboard de agentes, crear agentes, ver runs en tiempo real
